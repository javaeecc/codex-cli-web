# 会话过程展示标准

本文档是会话页面展示 Codex 工作过程的统一标准。后续涉及思考、工具调用、命令、文件操作和耗时展示的开发，都应遵循本文档。

## 展示层级

```text
总体思考
├─ 思考过程
│  └─ 思考文字内容
└─ 工作过程
   ├─ 执行命令
   ├─ 修改文件
   ├─ 查看文件
   ├─ 搜索代码
   ├─ 查看修改
   ├─ Git 操作
   └─ 其他操作
```

最终回答位于“总体思考”之外。

## 折叠规则

### 第一级：总体思考

- 运行中自动展开。
- 回合完成、取消或失败后自动折叠。
- 用户可以手动展开或折叠已结束的总体思考。
- 历史回放根据最终事件状态恢复：未结束的任务展开，已结束的任务折叠。

### 第二级：思考过程

- 展示用户可见的思考文字。
- 随总体思考一起显示。
- 运行期间可以展开查看当前文字。
- 不展示隐藏思维链，只展示协议明确发送到浏览器的可见文本。

### 第二级：工作过程

- 始终默认折叠，包括运行中状态。
- 用户点击后展开。
- 展开后按事件顺序显示第三级操作。
- 工作过程本身不因为子操作运行而自动展开。

### 第三级：具体操作

- 每个操作独立折叠。
- 默认折叠。
- 点击后查看具体命令、文件路径、补丁、输出、结果和退出码。
- 操作类型应使用明确名称，例如“执行命令”“修改文件”“查看文件”，不能无条件显示“工具调用”。

## 状态和耗时

每个展示节点都必须有独立状态和耗时。

### 总体思考

- 开始：`turn.started` 或等价的回合开始事件。
- 结束：`turn.completed`、`turn.cancelled` 或最终失败事件。
- 运行中显示“正在工作”和实时耗时。
- 结束后显示固定耗时，例如“耗时 20 秒”。

### 思考过程

- 开始：第一条可见思考文字事件。
- 结束：思考阶段结束或进入最终回答阶段。
- 运行中显示实时耗时。
- 结束后显示固定耗时。

### 工作过程

- 开始：第一个子操作开始事件。
- 结束：最后一个子操作完成事件。
- 运行中显示“正在工作”和实时耗时，但仍保持折叠。
- 结束后显示固定耗时。

### 第三级操作

- 开始：对应操作的 `started` 事件。
- 结束：对应操作的 `completed`、失败或取消事件。
- 运行中显示“正在工作”和实时耗时。
- 结束后显示固定耗时。

## 审批等待

- 总体思考耗时使用墙上时间，从回合开始到回合结束，因此包含审批等待时间。
- 具体命令耗时只计算该命令从开始到结束的时间，不把审批等待时间算入命令执行耗时。
- 工作过程在审批期间保持折叠，并显示等待状态；审批完成后继续更新后续操作。

## 历史数据

- 历史回放和实时事件必须使用同一套展示模型。
- 后端压缩历史事件时必须保留 `method`、`itemId`、`type`、命令、输出、退出码和状态等识别字段。
- 历史耗时使用事件时间计算，不能使用页面加载时间代替事件开始时间。
- 事件顺序必须保持：思考文字、工作过程和具体操作不能被统一移动到消息底部。

## 事件和类型识别

操作名称按以下优先级识别：

1. 事件方法，例如 `commandExecution`、`fileChange`、`fileRead`。
2. `item.type` 或 payload 中的类型字段。
3. 命令内容兜底识别，例如 `rg`、`grep` 归为“搜索代码”，`cat`、`Get-Content` 归为“查看文件”。
4. 无法识别时显示“其他操作”。

只有在无法识别具体类型时，才允许使用“其他操作”；“工具调用”不作为用户界面的默认名称。

## UI 一致性

- 第一级外框宽度与消息内容区对齐。
- 工作过程的内部操作列表略微收窄，命令和输出不得超出工作过程边界。
- 思考文字、工作过程和具体操作使用统一的左侧层级线和缩进。
- 运行中使用加载状态图标，完成后使用静态状态图标。
- 默认收起的内容不能因为增量事件刷新而意外改变用户手动设置的展开状态，除非发生明确的状态切换。
